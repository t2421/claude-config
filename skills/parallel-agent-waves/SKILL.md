# 並列サブエージェント波 (Parallel Agent Waves)

大量のタスクを、衝突・フレーク・半端なコミットを起こさずに並列で終わらせるための型。
前提: タスクが「1タスク = 1セッション」粒度で分解済み (目的 / 触るファイル / 受け入れ条件 /
スコープ外 が書かれている)。無ければ先に分解する。

## 役割分担

| 役割 | やること | やらないこと |
|---|---|---|
| オーケストレータ (自分) | 波の設計、エージェント起動、`build`・E2E・commit、ロードマップ状態更新、設計ログ追記 | 実装そのもの (小さな修正・spec 直しは例外) |
| サブエージェント | 割り当てタスクの実装 + 単体テスト緑 + 報告 | commit / 共有ドキュメント編集 / 本番ビルド / 他人のファイル |

理由: `next build` 等の重いビルドは同時実行でハングし、E2E の並列プロセスはフレークする。
commit と索引ファイル (ロードマップ・設計ログ) の同時編集は index 競合と履歴の混線を起こす。

## 手順

1. **所有権表を作る**: 各タスクが触るファイルを列挙し、重なるタスクは別の波へ。
   よく衝突するのは「登録ファイル」(ルーティング/ページ登録、デバッグフック、型定義、
   イベントランナー、バリデーションテスト、E2E ヘルパー)。これらは 1 波に 1 タスクまで
2. **ブリーフを渡す**: 下の雛形。「編集直前に再読・小さなハンク・他エージェントの所有ファイルは
   触らない・build/E2E/commit 禁止・報告に『未検証』を明記」を必ず入れる
3. **波を起動** (4〜6 並列が目安)。完了通知を待つ間に次の波の準備。E2E を書くエージェントは
   「配信中のビルドは凍結・src 禁止・自分の spec だけ実行」とし、**同時に走らせるのは 1〜2 本**
4. **波の終わりに検証**: `typecheck && test` → `build` → 配信 → フル E2E をバックグラウンド実行。
   その間に次の波 (ユニットレベルのタスク) を起動してよい
5. **緑になったら commit** (波ごとに 1 コミット、メッセージにタスク ID を列挙)。
   ロードマップの状態列を「済」に更新、設計判断は設計ログへ
6. **エージェントの発見を新タスクに起こす** (バランス破綻・迂回路・フックの前提違い など)。
   その場で直さず、ID を振って次の波に入れる

## エージェント・ブリーフ雛形

```
You are implementing task <ID> of <roadmap path>. Read its §<共通ブリーフ> and the task body first.
Work in <app dir>.
Task: <目的を 3〜6 行で。触るファイルを明示。受け入れ条件を箇条書き>
Constraints:
- run `<typecheck> && <unit test>` and keep them green
- do NOT run <heavy build> or <E2E runner> (the orchestrator runs them)   ← E2E 作成タスクは例外を明記
- do NOT git commit, do NOT edit <roadmap/design docs>
- other agents are editing <file list> concurrently — do not touch them; re-read shared files right before editing
Report: files changed, public signatures/event names, what you could not verify, and side findings (don't fix them).
```

## ハマりどころ

- **登録ファイルの同時編集**: 2 エージェントが同じファイルに追記すると片方の Edit が古い内容で失敗する。
  「編集直前に再読」で概ね解消。どうしても重なるなら波を分ける
- **E2E 作成エージェントの再実行ループ**: 緑を 2 回取るまで回し続けるので、オーケストレータが
  サーバーを落とすと巻き添えになる。フルスイートを回す前に `SendMessage` で止める
- **デバッグフックの前提**: E2E が使うフック (レベル付与・ワープ等) の仕様が「主人公だけ」など
  片手落ちだと、後半コンテンツで一斉に落ちる。最初の E2E タスクでフックを見直す
- **レート制限で落ちたエージェント**: 途中編集が残る。`git status` で差分を見て、引き継ぐか戻すかを決める
- **並列時のフレーク判定**: 失敗テストは単体で再実行して判定 (単体で緑なら環境起因)

## 完了の定義

- ロードマップの全タスクが「済」か「保留 (理由・判断者つき)」
- フル E2E 緑のビルドが commit 済み
- 設計ログに日付つきの確定事項、リリースチェックリストに人手確認項目が残っている
